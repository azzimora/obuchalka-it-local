AI-агент

пять компонентов, ReAct-цикл, мультиагентные системы
главная› AI›05
◈ теория

До этого мы работали с моделями, которые отвечают на вопросы. Ты пишешь — они отвечают. Это пассивная роль: модель реагирует, но ничего не делает сама.

Но AI может не только отвечать — он может действовать.

Эволюция: от чат-бота к агенту

  • Чат-бот — отвечает по заранее прописанным сценариям. Никакого AI внутри, только if-else логика. «Напишите 1 — узнать баланс, 2 — связаться с оператором».
  • Ассистент — языковая модель, которая помнит контекст и отвечает умно. Это то, с чем мы работали. ChatGPT и Claude в обычном режиме — ассистенты. Они умны, но ничего не делают за пределами чата.
  • Агент — языковая модель, которая умеет не только отвечать, но и выполнять действия: искать в интернете, запускать код, отправлять письма, работать с файлами. Агент получает задачу и сам решает, какие шаги предпринять.
  • Мультиагентная система — несколько агентов работают вместе. Каждый специализируется на своей части задачи.
Чат-бот → Ассистент → Агент → Мультиагент
(правила)  (понимает)  (действует)  (команда)

Пять компонентов агента

Любой AI-агент состоит из пяти частей. Понимая их, ты понимаешь любой агент — простой или сложный.

1. LLM (мозг).
Языковая модель принимает решения. Она получает информацию о текущей ситуации и решает: что делать дальше, какой инструмент использовать, достигнута ли цель. Именно LLM даёт агенту гибкость — он может адаптироваться к неожиданным ситуациям.

2. Память.
У агента два вида памяти:

  • Краткосрочная — контекст текущей сессии. Всё, что происходило с начала задачи: вопросы, промежуточные результаты, ошибки.
  • Долгосрочная — база, которая сохраняется между сессиями. Предпочтения пользователя, результаты прошлых задач, накопленные знания.
short_term_memory = [
  {"action": "search", "query": "погода в Москве", "result": "15°C, пасмурно"},
  {"action": "think",  "reasoning": "нужно уточнить дату"}
]

long_term_memory = {
  "user_preferences": {"city": "Москва", "units": "celsius"},
  "past_tasks": ["составил план поездки 15.03"]
}

3. Инструменты (Tools).
Это то, что агент может делать. Каждый инструмент — функция, которую агент может вызвать.

Типичные инструменты:

  • поиск в интернете;
  • запуск кода;
  • чтение и запись файлов;
  • отправка email;
  • запросы к API (погода, курсы валют, база данных);
  • работа с браузером.
tools = [
  { "name": "web_search",
    "description": "Поиск информации в интернете",
    "parameters": {"query": "строка поиска"} },
  { "name": "run_python",
    "description": "Запускает Python-код",
    "parameters": {"code": "код для выполнения"} },
  { "name": "write_file",
    "description": "Записывает текст в файл",
    "parameters": {"filename": "...", "content": "..."} }
]

Ключевая идея: агент не программируется вызывать инструменты в определённом порядке. LLM сам решает — исходя из задачи — какой инструмент нужен сейчас.

4. Цель (Goal).
Задача, которую агент должен решить. В отличие от обычного промпта, цель агента может быть высокоуровневой и многошаговой.

Обычный промпт:
"Найди информацию о Python"
→ ответ: текст про Python

Цель агента:
"Изучи три популярных Python-фреймворка,
сравни их по скорости и документации,
напиши краткий отчёт в файл report.md"
→ агент: ищет, анализирует, создаёт файл — сам

5. Оркестратор.
Логика, которая управляет работой агента: когда вызвать инструмент, когда спросить пользователя, когда считать задачу выполненной. В простых агентах оркестратором является сам LLM. В сложных системах — отдельный код или отдельный агент.

ReAct-цикл

Большинство агентов работают по циклу ReAct (Reason + Act).

Reason → Act → Observe → Reason → ...

Разберём на задаче «Узнай погоду в Москве и запиши в файл»:

  • Шаг 1 — Reason: «Мне нужна погода в Москве. У меня есть инструмент web_search. Использую его с запросом "погода Москва сегодня"».
  • Шаг 2 — Act: вызов web_search("погода Москва сегодня").
  • Шаг 3 — Observe: «Результат: в Москве 12°C, облачно, без осадков».
  • Шаг 4 — Reason: «Данные есть. Теперь нужно записать в файл. Использую write_file».
  • Шаг 5 — Act: вызов write_file("weather.txt", "Москва: 12°C, облачно").
  • Шаг 6 — Observe: «Файл создан».
  • Шаг 7 — Reason: «Задача выполнена. Завершаю».

Этот цикл может повторяться десятки раз для сложных задач. Агент продолжает рассуждать и действовать, пока не достигнет цели.

def react_agent(goal, tools, memory):
    while not goal_achieved:
        decision = llm.think(goal, tools, memory)
        if decision.type == "use_tool":
            result = tools[decision.tool_name].run(decision.parameters)
            memory.add(decision, result)
        elif decision.type == "ask_user":
            user_input = ask_user(decision.question)
            memory.add(user_response=user_input)
        elif decision.type == "finish":
            goal_achieved = True
            return decision.final_answer

Файловая структура агента

Реальный агент — не одна программа, а набор файлов.

my_agent/
├── system_prompt.md      # личность, роль, ограничения
├── config.yaml           # технические настройки
├── skills/               # инструменты
│   ├── web_search.py
│   ├── run_code.py
│   └── write_file.py
├── memory/               # долгосрочная память
│   └── user_preferences.json
└── workflows/            # готовые сценарии
    └── daily_report.yaml
  • system_prompt.md — роль, характер, правила.
  • config.yaml — модель, температура, лимиты.
  • skills/ — каждый инструмент в отдельном файле.
  • memory/ — долгосрочная память (JSON или база).
  • workflows/ — готовые сценарии для типичных задач.

Мультиагентные системы

Один агент хорош для простых задач. Для сложных — нужна команда.

Пример: задача «Подготовь отчёт о рынке электромобилей».

  • Агент-исследователь — ищет статьи, собирает статистику, передаёт аналитику.
  • Агент-аналитик — получает данные, анализирует тренды, делает выводы, передаёт редактору.
  • Агент-редактор — оформляет в читаемый отчёт, проверяет структуру, выдаёт финал.

Преимущества:

  • каждый агент специализирован и работает лучше в своей области;
  • задачи выполняются параллельно;
  • легче масштабировать.

Оркестратор-агент управляет всей системой: распределяет задачи, следит за прогрессом, собирает результаты.

Главное из темы

  • Агент — это модель, которая умеет действовать, а не только отвечать.
  • Пять компонентов: LLM, память, инструменты, цель, оркестратор.
  • ReAct-цикл: Reason → Act → Observe → повтор.
  • Агент сам решает, какой инструмент использовать.
  • Мультиагентные системы — команда специализированных агентов.
