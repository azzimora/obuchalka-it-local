Оркестраторы

управление агентами, MCP и мультиагентные системы
главная› AI›06
◈ теория

Оркестратор — это система, которая управляет работой агента или команды агентов. Она решает: какой шаг сделать, какой инструмент вызвать, когда остановиться, как передать результат дальше.

Важно понимать: слово «оркестратор» используется в двух смыслах.

  • В узком смысле — компонент внутри одного агента, который решает, какой инструмент вызвать. Мы уже говорили о нём в теме 05.
  • В широком смысле — отдельная система, которая управляет целой командой агентов и их взаимодействием. Это то, о чём эта тема.

Зачем нужен отдельный оркестратор

  • В простом агенте оркестратором выступает сама LLM — она сама решает, что делать.
  • В сложных системах логика выносится в отдельный слой: код, граф или отдельный агент-координатор.
  • Это даёт контроль: можно задать жёсткие правила, лимиты, точки проверки, где человек должен подтвердить действие.

Два подхода к оркестрации

Кодовые оркестраторы — логика прописана в коде. Примеры: LangChain, CrewAI, AutoGen, Microsoft Agent Framework.

Визуальные оркестраторы — логика собирается из блоков мышкой. Примеры: n8n, Make, Zapier.

Что умеет визуальный оркестратор (на примере n8n)

  • Триггеры — что запускает сценарий: новое письмо, время, вебхук, сообщение в чате.
  • Узлы действий — что делать: запрос к AI, отправка письма, запись в базу, HTTP-запрос.
  • Логика — условия, циклы, ветвления, ожидание.
  • Связи — как данные передаются от узла к узлу.

Типичный workflow с AI:

Триггер: новое сообщение в Telegram
    ↓
Узел 1: классифицировать сообщение через AI
    ↓
Узел 2: если жалоба — уведомить отдельный канал
    ↓
Узел 3: если вопрос — сгенерировать ответ
    ↓
Узел 4: записать всё в таблицу

MCP — стандарт подключения инструментов

MCP (Model Context Protocol) — открытый протокол, созданный Anthropic. Он определяет, как AI-приложения подключаются к внешним инструментам и данным через единый интерфейс. В декабре 2025 Anthropic передала MCP в Agentic AI Foundation под управление Linux Foundation, чтобы стандарт развивался независимо от одной компании.

Аналогия: MCP — это как USB-разъём. Вместо того чтобы делать свой разъём для каждого устройства, все используют один стандарт. Так и здесь: вместо M×N интеграций (каждое приложение × каждый инструмент) получается M+N.

Архитектура MCP — три роли:

  • Host — приложение, с которым работает пользователь (Claude Desktop, Cursor, VS Code). Управляет клиентами и политиками безопасности.
  • Client — коннектор внутри host, поддерживает соединение с одним сервером.
  • Server — программа, которая предоставляет свои возможности через MCP.

Сервер предоставляет три типа возможностей:

  • Resources — данные для контекста: файлы, записи, документация. Управляются приложением-хостом.
  • Tools — исполняемые функции, которые может вызвать модель: поиск, отправка, запись. Управляются моделью.
  • Prompts — шаблоны инструкций, которые выбирает пользователь (слэш-команды, пункты меню).

Правило простое: tools — модель выбирает как действие, resources — приложение включает как контекст, prompts — пользователь выбирает как инструкцию.

Безопасность MCP

MCP даёт мощные возможности: доступ к данным и выполнение кода. С этим приходят и риски.

Явное согласие пользователя. Протокол требует, чтобы пользователь явно подтверждал доступ к данным и вызов каждого инструмента. Описания инструментов от недоверенных серверов нельзя считать надёжными — их нужно проверять.

Rug-pull-атака. Это атака, когда определение инструмента на сервере тайно меняется после первоначального одобрения. Например, доверенный инструмент «send_slack_message» позже изменяется так, чтобы выполнять эксфильтрацию данных. Агент вызывает его, думая, что он безопасен. Поэтому рекомендуется проверять целостность инструментов и использовать MCP-шлюзы безопасности, которые следят за изменениями.

Prompt injection. Вредоносный агент или инструмент может внедрить инструкции, которые выглядят как обычные ответы, и заставить агента выполнить нежелательные действия. Защита — строгая идентификация, ограничение прав и контроль цепочки поставок.

Microsoft Agent Framework

Это фреймворк от Microsoft, прямой наследник Semantic Kernel и AutoGen. Он объединяет простые абстракции AutoGen с enterprise-возможностями Semantic Kernel: управление состоянием сессий, типизация, middleware, телеметрия.

Ключевая особенность — workflows: графовые рабочие процессы, которые соединяют агентов и функции через явные пути исполнения. Это даёт разработчику точный контроль над порядком и логикой мультиагентных систем.

Фреймворк поддерживает подключение к Microsoft Foundry, Anthropic, Azure OpenAI, OpenAI, Ollama и другим провайдерам. MCP-клиенты встроены для подключения инструментов.

Сравнение n8n и CrewAI

n8n CrewAI
Тип Визуальный low-code Кодовый (Python)
Для чего Автоматизация, интеграции Команды агентов с ролями
Плюсы Быстро, визуально, не нужен код Гибко, для сложных архитектур
Минусы Сложно, когда логика глубоко вложена Требует программирования
Когда выбирать Агент — часть большого workflow Нужна команда специализированных агентов

Главное из темы

  • Оркестратор — в широком смысле система управления агентами, в узком — компонент внутри агента.
  • Кодовые оркестраторы: LangChain, CrewAI, Microsoft Agent Framework.
  • Визуальные: n8n, Make, Zapier.
  • MCP — стандарт подключения инструментов: три примитива (Tools, Resources, Prompts).
  • Безопасность MCP: явное согласие, проверка инструментов, защита от rug-pull и prompt injection.
  • Выбор оркестратора зависит от сложности задачи и навыков команды.
✦ домашка

Цель: разобраться, как устроена автоматизация с AI, и спроектировать свой workflow.

  • Задание 1 — спроектируй workflow.
    Придумай задачу, которую хочется автоматизировать (например, «сортировать входящие сообщения по важности»). Опиши workflow по шагам: триггер → узлы → результат. Что делает каждый узел и зачем.
  • Задание 2 — нарисуй схему связей.
    Откуда приходят данные, куда идут, где стоит AI, где логика. Ответь: какой узел самый важный и почему; что произойдёт, если AI вернёт неожиданный ответ; как добавить память между запусками.
  • Задание 3 — разбери MCP-примитивы.
    Придумай MCP-сервер для вымышленного сервиса (например, для библиотеки). Какие ресурсы он будет предоставлять? Какие инструменты? Какие промпты? Запиши.
  • Задание 4 — придумай защиту от rug-pull.
    Представь, что ты строишь систему, которая подключает сторонние MCP-серверы. Какие меры безопасности ты бы применил? Запиши минимум 3.
  • Задание 5 — выбери оркестратор.
    Для трёх задач определи, какой оркестратор подошёл бы лучше — n8n, CrewAI или Microsoft Agent Framework. Объясни выбор для каждой.
    • Сортировка писем в Gmail;
    • Исследование рынка с написанием отчёта;
    • Бот поддержки, который отвечает на вопросы по документации.
