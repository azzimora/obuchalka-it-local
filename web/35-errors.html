Обработка ошибок: try / catch

как сделать код устойчивым к сбоям
главная› Web›35
◈ теория

Ошибки случаются. Пользователь ввёл не то, сервер не ответил, файл не найден, интернет пропал. Хороший код умеет с этим работать — а не падать.

В этой теме — как ловить ошибки и что с ними делать.

Что такое ошибка в JS

Когда в коде что-то не так, JS создаёт объект Error и «выбрасывает» его (throw). Если никто не поймал — программа останавливается, и в консоли появляется красное сообщение.

console.log(undefinedVariable);
// ReferenceError: undefinedVariable is not defined

try / catch

Конструкция, которая ловит ошибки:

try {
  // код, где может быть ошибка
  console.log(undefinedVariable);
} catch (error) {
  // что делать, если ошибка
  console.log("поймана ошибка:", error.message);
}

console.log("программа продолжает работать");

Если в try что-то падает — управление переходит в catch. Программа не останавливается.

finally — выполняется всегда

try {
  console.log("в try");
} catch (error) {
  console.log("в catch");
} finally {
  console.log("в finally — всегда");
}

finally полезен, когда надо что-то «прибрать» — независимо от того, была ошибка или нет.

Объект Error

У ошибки есть полезные свойства:

  • error.message — текст ошибки;
  • error.name — тип ошибки;
  • error.stack — стек вызовов (где именно упало).
try {
  null.foo;
} catch (error) {
  console.log(error.name);     // "TypeError"
  console.log(error.message);  // "Cannot read properties of null"
}

Типы ошибок

Название Когда бывает
ReferenceError Переменная не существует
TypeError Действие с неподходящим типом
SyntaxError Ошибка в синтаксисе (обычно ловится при загрузке)
RangeError Число вне допустимого диапазона
Custom Error Своя ошибка через throw

throw — выбросить свою ошибку

Иногда нужно сообщить об ошибке самому:

function divide(a, b) {
  if (b === 0) {
    throw new Error("делить на ноль нельзя");
  }
  return a / b;
}

try {
  console.log(divide(10, 0));
} catch (error) {
  console.log("ошибка:", error.message);  // "делить на ноль нельзя"
}

Так функция говорит: «я не могу это сделать, вот причина».

Свои классы ошибок

Можно создавать свои типы ошибок, чтобы различать их:

class ValidationError extends Error {
  constructor(message) {
    super(message);
    this.name = "ValidationError";
  }
}

try {
  throw new ValidationError("email неверный");
} catch (error) {
  if (error.name === "ValidationError") {
    console.log("проблема с данными:", error.message);
  } else {
    console.log("другая ошибка:", error.message);
  }
}

try / catch в async / await

Это самое частое применение. Любой await может упасть — его надо ловить:

async function loadData() {
  try {
    const response = await fetch("https://api.example.com/data");
    
    if (!response.ok) {
      throw new Error(`Сервер вернул ${response.status}`);
    }
    
    const data = await response.json();
    return data;
  } catch (error) {
    console.log("не удалось загрузить:", error.message);
    return null;
  }
}

Promise.catch

Если работаешь без async / await, ошибки ловятся через .catch():

fetch("https://api.example.com/data")
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.log("ошибка:", error.message));

Что делать с ошибкой в catch

Поймать ошибку — это полдела. Дальше надо решить, что с ней делать. Вариантов несколько:

  • Показать пользователю понятное сообщение. «Не удалось загрузить данные» вместо красной ошибки в консоли.
  • Записать в лог. console.error() для разработки.
  • Попробовать снова. Если ошибка временная — повторить запрос.
  • Использовать запасной вариант. Например, загрузить данные из кэша.
  • Пробросить дальше. Если не можешь обработать сама — пусть разбирается вызывающий код.

Чего не делать

Не глотай ошибки молча:

try {
  dangerousOperation();
} catch (error) {
  // пусто — ошибка исчезла, но проблема осталась
}

Это худшее, что можно сделать. Никто не узнает, что что-то сломалось.

Не лови ошибку, если не знаешь, что с ней делать:

try {
  const result = complexFunction();
} catch (error) {
  console.log("что-то пошло не так");  // ← а что именно? и что делать?
}

Не используй try / catch для обычной логики:

// плохо — try / catch для проверки условия
try {
  if (user.age < 18) throw new Error("мало лет");
} catch (error) { /* ... */ }

// хорошо — обычный if
if (user.age < 18) {
  console.log("мало лет");
}

Глобальный обработчик ошибок

Можно поймать все непойманные ошибки в одном месте:

window.addEventListener("error", event => {
  console.log("глобальная ошибка:", event.message);
});

window.addEventListener("unhandledrejection", event => {
  console.log("непойманный Promise:", event.reason);
});

Полезно для отладки и логирования.

Паттерн: безопасная функция

Часто полезно сделать функцию, которая не падает:

async function safeFetch(url) {
  try {
    const response = await fetch(url);
    if (!response.ok) throw new Error(`статус ${response.status}`);
    return { ok: true, data: await response.json() };
  } catch (error) {
    return { ok: false, error: error.message };
  }
}

const result = await safeFetch("/api/data");
if (result.ok) {
  console.log(result.data);
} else {
  console.log("ошибка:", result.error);
}

Вместо того чтобы бросать ошибку, функция возвращает объект с полем ok. Так вызывающий код явно проверяет результат.

Главное из темы

  • try / catch ловит ошибки, finally выполняется всегда.
  • Ошибка — это объект с message, name, stack.
  • throw new Error() — выбросить свою ошибку.
  • Можно создавать свои классы ошибок.
  • Любой await должен быть в try / catch.
  • Не глотай ошибки молча. Не лови, если не знаешь, что делать.
  • Для API удобен паттерн «безопасная функция» с полем ok.
✦ домашка

Цель: научиться ловить ошибки и делать код устойчивым.

  • Создай файл errors.html с обычным каркасом. Открой, F12 → Console.
  • Задание 1 — первый try / catch. Напиши код, который обращается к несуществующей переменной, оберни в try / catch, выведи error.name и error.message.
  • Задание 2 — finally. Сделай try / catch / finally. В try — ошибка, в catch — обработка, в finally — сообщение «завершено». Убедись, что finally выполняется.
  • Задание 3 — своя ошибка. Напиши функцию checkAge(age), которая выбрасывает ошибку, если возраст меньше 18 или больше 120. Оберни вызов в try / catch. Проверь с разными значениями.
  • Задание 4 — свой класс ошибок. Создай класс ValidationError extends Error. Напиши функцию validateEmail(email), которая выбрасывает ValidationError, если email без «@». Поймай и обработай отдельно от других ошибок.
  • Задание 5 — try / catch в async. Сделай запрос к несуществующему URL через fetch. Оберни в try / catch. Выведи понятное сообщение об ошибке. (Подсказка: fetch без интернета или с неверным URL выбросит ошибку.)
  • Задание 6 — безопасная функция. Напиши safeFetch(url) из теории. Используй её для запроса к https://jsonplaceholder.typicode.com/posts/1. Проверь результат через if (result.ok).
  • Задание 7 — на странице. Сделай кнопку, при клике на которую загружаются данные. Если ошибка — показать понятное сообщение и кнопку «попробовать снова». Стилизуй красиво.
  • Бонус — глобальный обработчик. Добавь window.addEventListener("error", ...). Убедись, что непойманные ошибки попадают туда.
