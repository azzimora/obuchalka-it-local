Это финал продвинутого JS. Здесь нужно собрать всё, что было изучено, в одну настоящую работу. Не учебное упражнение, а проект, который можно показать.

Что должно быть использовано:

  • async / await — для запросов;
  • fetch — для получения данных из API;
  • обработка ошибок — try / catch, состояния загрузки;
  • модули — код разбит на файлы;
  • классы — хотя бы один, для логики;
  • localStorage — для сохранения данных;
  • debounce — если есть поиск;
  • CSS — красиво, адаптивно, с анимациями.

Формат проекта

Выбери одно из направлений — или придумай своё.

Вариант 1 — Приложение с публичным API

Страница, которая берёт данные из открытого API и красиво их показывает.

Примеры:

  • Погода — через Open-Meteo. Вводишь город, получаешь погоду на неделю.
  • Поиск книг — через Google Books API. Вводишь название — список книг с обложками.
  • Факты о котах — через Cat Fact. Кнопка «новый факт».
  • Галерея фото — через Pexels или Unsplash. Поиск по ключевому слову.
  • Пользователи GitHub — через GitHub API. Вводишь ник — карточка пользователя.

Вариант 2 — Личный трекер

Приложение, которое что-то отслеживает и сохраняет.

Примеры:

  • Трекер привычек — отмечаешь, что сделано, видишь прогресс;
  • Дневник тренировок — записываешь упражнения, видишь статистику;
  • Список фильмов — добавляешь, отмечаешь просмотренные, ставишь оценки;
  • Дневник настроения — каждый день отмечаешь настроение, видишь динамику.

Вариант 3 — Мини-игра

Игра на JS с сохранением прогресса.

Примеры:

  • Викторина — вопросы, ответы, подсчёт очков, рейтинг;
  • Угадай число — с подсказками и попытками;
  • Мемори — карточки с парами, счётчик ходов;
  • Змейка — классика на canvas;
  • 2048 — с сохранением рекорда.

Вариант 4 — Своя идея

Если есть что-то своё — что угодно. Главное, чтобы выполнялись требования.

Требования к проекту

Структура:

my-project/
├── index.html
├── css/
│   └── style.css
├── js/
│   ├── main.js          # точка входа
│   ├── api.js           # запросы к API (если есть)
│   ├── storage.js       # работа с localStorage
│   └── ui.js            # отрисовка
└── README.md            # описание проекта

Что использовать обязательно:

  • type="module" для скриптов;
  • минимум два модуля (main + один ещё);
  • хотя бы один класс;
  • async / await (если есть запросы);
  • try / catch для обработки ошибок;
  • localStorage для сохранения данных;
  • три состояния интерфейса: загрузка / успех / ошибка (если есть запросы).

Стиль и адаптив:

  • тёмная тема или своя;
  • адаптив — работает на телефоне;
  • минимум одна CSS-анимация;
  • hover-эффекты на кликабельных элементах;
  • шрифты не меньше 14px;
  • кликабельные зоны не меньше 40px.

Качество кода:

  • осмысленные имена переменных и функций;
  • одна функция — одна задача;
  • комментарии к сложным местам;
  • нет ошибок в консоли.

План работы

Не пиши всё сразу. Так делают профессионалы:

  1. Идея. Что это, для кого, зачем. Одна фраза.
  2. Структура. Какие файлы, какие функции, какой класс. На бумаге или в комментариях.
  3. HTML. Скелет страницы. Без стилей, без JS.
  4. CSS. Оформление. Тёмная тема, акценты, отступы.
  5. JS: логика без API. Если есть localStorage — сначала с ним. Проверь, что всё работает.
  6. JS: API. Если есть запросы — добавь fetch, состояния, обработку ошибок.
  7. Разбей на модули. Вынеси логику, API, отрисовку в отдельные файлы.
  8. Полировка. Анимации, hover, адаптив, мелочи.
  9. README. Опиши проект: что это, как запустить, что использовано.

Как проверить готовность

Перед сдачей проверь:

  • Проект открывается через Live Server без ошибок;
  • Все кнопки работают, всё кликабельно;
  • В консоли нет красных ошибок;
  • Данные сохраняются после перезагрузки (если есть localStorage);
  • Работает на телефоне (DevTools, Ctrl+Shift+M);
  • Загрузка и ошибки отображаются понятно;
  • Код разбит на модули, а не всё в одном файле;
  • Есть хотя бы один класс.

Куда двигаться дальше

После этого проекта ты знаешь:

  • HTML, CSS, JS на уверенном уровне;
  • асинхронность, API, модули, классы;
  • как организовать код в проекте.

Что можно изучать дальше, если захочется:

  • React, Vue или Svelte — фреймворки для интерфейсов;
  • TypeScript — JS с типами;
  • Node.js — JS на сервере;
  • Vite — современная сборка проектов;
  • Git и GitHub — для работы в команде и портфолио.

Это уже следующий уровень. Сначала — проект.

✦ домашка

Цель: сделать один полноценный проект целиком.

  • Выбери вариант:
    • приложение с API;
    • личный трекер;
    • мини-игра;
    • своя идея.
  • Создай структуру папок — index.html, css/, js/ с модулями, README.md.
  • Пройди по шагам плана: идея → структура → HTML → CSS → логика → API → модули → полировка.
  • Обязательно используй:
    • модули (import / export);
    • минимум один класс;
    • async / await (если есть запросы);
    • try / catch;
    • localStorage;
    • CSS-анимацию и адаптив.
  • Проверь готовность по списку выше. Особенно: нет ошибок в консоли, работает на телефоне, данные сохраняются.
  • Напиши README.md — описание проекта, как запустить, что использовано. Это важно: без README проект выглядит незаконченным.
  • Бонус: опубликуй на GitHub Pages или Netlify — получишь публичную ссылку. Это уже портфолио.
  • В поле ниже запиши: что за проект, что получилось, что было сложно, что хотелось бы добавить.

Проект можно делать несколько дней. Не торопись. Это финал — сделай так, чтобы было не стыдно показать.
