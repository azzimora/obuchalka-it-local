Модули: import / export

как разбивать код на файлы
главная› Web›32
◈ теория

До этой темы весь JS жил в одном файле. Для маленьких проектов это нормально. Но когда код растёт — один файл на 1000 строк становится кашей. Ничего не найти, ничего не переиспользовать.

Модули решают эту проблему: код разбивается на отдельные файлы, каждый со своей задачей.

Как это работает

Один файл экспортирует (отдаёт) что-то наружу. Другой файл импортирует (берёт) это к себе.

Аналогия: библиотека. Каждая книга — отдельный «модуль». Ты берёшь с полки нужную, а не всю библиотеку сразу.

Экспорт

Есть два вида экспорта.

Named export — именованный. Можно экспортировать несколько вещей из одного файла:

// math.js

export function add(a, b) {
  return a + b;
}

export function subtract(a, b) {
  return a - b;
}

export const PI = 3.14159;

Default export — экспорт по умолчанию. Один на файл:

// greet.js

export default function greet(name) {
  return `Привет, ${name}!`;
}

Импорт

Named-импорт:

// main.js

import { add, subtract, PI } from "./math.js";

console.log(add(2, 3));      // 5
console.log(subtract(5, 1)); // 4
console.log(PI);             // 3.14159

Default-импорт:

// main.js

import greet from "./greet.js";

console.log(greet("Аня"));

Разница: named импортируется в { }, default — без. Имя default-импорта можно выбрать любое, имя named-импорта должно совпадать с тем, что было экспортировано.

Импорт всего сразу

Можно импортировать все named-экспорты как объект:

import * as math from "./math.js";

console.log(math.add(2, 3));
console.log(math.PI);

Переименование при импорте

Иногда имя занято или неудобное — можно переименовать:

import { add as sum, PI as pi } from "./math.js";

console.log(sum(2, 3));

Как подключить модули в HTML

Важно: для модулей нужно указать атрибут type="module" у тега script.

<script type="module" src="main.js"></script>

Без этого браузер не поймёт import и export.

Важное ограничение: локальные файлы

Если просто открыть HTML-файл двойным кликом (через file://), модули не будут работать — браузер заблокирует их по соображениям безопасности.

Чтобы модули работали, нужен локальный сервер. Способы:

  • VS Code + расширение Live Server. Установи расширение Live Server, правой кнопкой по HTML → «Open with Live Server». Это самый простой способ.
  • Командная строка: в папке с проектом напиши python -m http.server (если установлен Python) — и открой http://localhost:8000.
  • Публикация на GitHub Pages / Netlify. Там сервер есть изначально.

Это не проблема — просто особенность разработки. Все реальные проекты запускаются через сервер.

Структура проекта с модулями

Типичный проект выглядит так:

my-project/
├── index.html
├── main.js              ← главный файл, который импортирует
└── modules/
    ├── api.js           ← запросы к API
    ├── ui.js            ← работа с DOM
    ├── utils.js         ← вспомогательные функции
    └── storage.js       ← localStorage

В каждом файле — своя зона ответственности. Главный main.js их связывает.

Пример: разбиваем todo на модули

storage.js — сохранение:

const KEY = "todos";

export function load() {
  return JSON.parse(localStorage.getItem(KEY) || "[]");
}

export function save(todos) {
  localStorage.setItem(KEY, JSON.stringify(todos));
}

ui.js — отрисовка:

export function render(todos) {
  const list = document.getElementById("list");
  list.innerHTML = "";
  todos.forEach((todo, i) => {
    const li = document.createElement("li");
    li.textContent = todo;
    list.appendChild(li);
  });
}

main.js — связка:

import { load, save } from "./modules/storage.js";
import { render } from "./modules/ui.js";

let todos = load();
render(todos);

document.getElementById("add").addEventListener("click", () => {
  const input = document.getElementById("input");
  if (!input.value.trim()) return;
  
  todos.push(input.value.trim());
  input.value = "";
  save(todos);
  render(todos);
});

Каждый файл делает одно. Легко найти, легко поменять, легко переиспользовать.

Когда нужны модули

  • Проект больше 200–300 строк JS;
  • Есть повторяющиеся функции (например, работа с API);
  • Хочется разделить логику и интерфейс;
  • Над проектом работает несколько человек;
  • Планируется переиспользовать код в другом проекте.

Для маленьких скриптов модули — лишнее. Не всё надо разбивать.

Главное из темы

  • Модули — способ разбить код на файлы.
  • export отдаёт, import берёт.
  • Named-экспорт: export function name() {}, импорт в { }.
  • Default-экспорт: export default function() {}, импорт без { }.
  • В HTML — <script type="module">.
  • Модули работают только через локальный сервер (Live Server).
