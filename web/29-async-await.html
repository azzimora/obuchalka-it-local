async / await

современный способ писать асинхронный код
главная› Web›29
◈ теория

Promise — это хорошо, но цепочки .then() читать неудобно, особенно когда их много. Поэтому придумали async / await — синтаксис, который делает асинхронный код похожим на обычный, синхронный.

async / await — это не замена Promise. Это «обёртка» над ним, которая читается проще.

Сравни

С Promise:

function loadData() {
  return fetch("/api/data")
    .then(response => response.json())
    .then(data => {
      console.log(data);
      return data;
    })
    .catch(error => {
      console.log("ошибка:", error);
    });
}

С async / await:

async function loadData() {
  try {
    const response = await fetch("/api/data");
    const data = await response.json();
    console.log(data);
    return data;
  } catch (error) {
    console.log("ошибка:", error);
  }
}

Второй вариант читается как обычный код: «получи ответ, потом преобразуй, потом выведи». Никаких цепочек.

Как это работает

Два ключевых слова:

  • async — ставится перед функцией. Говорит: «эта функция асинхронная, она возвращает Promise».
  • await — ставится перед Promise. Говорит: «подожди результат, прежде чем идти дальше».
async function example() {
  const result = await somePromise();
  console.log(result);  // выполнится после того, как Promise разрешится
}

Важно: await работает только внутри async-функции. Вне её — синтаксическая ошибка.

Что возвращает async-функция

Всегда возвращает Promise. Даже если внутри возвращается обычное значение.

async function greet() {
  return "привет";
}

greet().then(msg => console.log(msg));  // "привет"

Поэтому async-функцию можно использовать там же, где Promise: с .then(), Promise.all() и т.д.

Обработка ошибок: try / catch

Вместо .catch() используется обычный try / catch — как в синхронном коде.

async function loadUser() {
  try {
    const response = await fetch("/api/user");
    const user = await response.json();
    return user;
  } catch (error) {
    console.log("не получилось:", error);
    return null;
  }
}

Если что-то упадёт на любом await — управление перейдёт в catch.

Последовательное выполнение

Один из главных плюсов: код читается сверху вниз.

async function process() {
  const a = await step1();
  console.log("шаг 1 готов");
  
  const b = await step2(a);
  console.log("шаг 2 готов");
  
  const c = await step3(b);
  console.log("шаг 3 готов");
  
  return c;
}

Понятно, что происходит. Никаких «а где тут .then?».

Параллельное выполнение

Если операции не зависят друг от друга, можно запустить их параллельно и подождать все сразу через Promise.all:

async function loadAll() {
  const [users, posts, comments] = await Promise.all([
    fetch("/api/users").then(r => r.json()),
    fetch("/api/posts").then(r => r.json()),
    fetch("/api/comments").then(r => r.json())
  ]);
  
  console.log(users, posts, comments);
}

Три запроса идут одновременно. Ждём все. Это быстрее, чем последовательно.

Чего не делать

Не стоит использовать await в цикле, если можно сделать иначе:

// медленно: каждая итерация ждёт предыдущую
for (const id of ids) {
  const user = await fetchUser(id);
  users.push(user);
}

// быстро: все запросы параллельно
const users = await Promise.all(
  ids.map(id => fetchUser(id))
);

Первый вариант выполняет запросы по очереди. Второй — сразу все.

Promise vs async / await: когда что

  • async / await — почти всегда. Читается лучше, ошибки ловятся проще.
  • Promise — когда нужно передать «обещание» куда-то без ожидания, или когда работаешь с короткой цепочкой.
  • Promise.all — внутри async-функций, для параллельных операций.

На практике современный JS на 90% пишется на async / await.

Главное из темы

  • async — перед функцией. await — перед Promise.
  • await работает только внутри async-функции.
  • Ошибки ловятся через try / catch.
  • async-функция всегда возвращает Promise.
  • Для параллельных операций — Promise.all внутри async-функции.
  • Не используй await в цикле, если можно сделать параллельно.
