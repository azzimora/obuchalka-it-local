Асинхронность: что это и зачем

почему код иногда «ждёт» и как с этим жить
главная› Web›26
◈ теория

До этой темы весь JS, который мы писали, был синхронным. Это значит: код выполняется строка за строкой, сверху вниз. Каждая следующая строка ждёт, пока закончится предыдущая.

Для простых задач это нормально. Но есть вещи, которые занимают время:

  • запрос к серверу (получить данные с сайта);
  • чтение файла с диска;
  • таймер («подожди 3 секунды»);
  • загрузка картинки.

Если бы JS ждал каждую такую операцию, страница бы замирала. Кнопки не нажимались бы, анимации останавливались. Поэтому придумали асинхронность.

Синхронный код: как это работает

console.log("1");
console.log("2");
console.log("3");

Вывод:

1
2
3

Просто и предсказуемо. Каждая строка ждёт предыдущую.

Что, если одна операция занимает время

Представь, что вторая строка — это запрос к серверу, который идёт 2 секунды. Что будет?

console.log("1");
// ← здесь код ждёт 2 секунды, страница замерла
console.log("2");
console.log("3");

Первая секунда — страница не отвечает. Кнопки не работают. Это плохо.

Асинхронный код: как это работает

Асинхронный JS не ждёт. Он отправляет задачу и идёт дальше, а когда результат готов — возвращается к нему.

Аналогия: ты заказываешь пиццу. Ты не стоишь у двери 30 минут — ты занимаешься своими делами, а когда курьер звонит, открываешь. Это асинхронность.

console.log("1");

setTimeout(() => {
  console.log("2 (через 2 секунды)");
}, 2000);

console.log("3");

Вывод:

1
3
2 (через 2 секунды)

Обрати внимание: «3» вывелось раньше, чем «2», хотя в коде стоит позже. Потому что setTimeout не блокирует выполнение — он просто говорит: «через 2 секунды выполни вот это». А пока — код идёт дальше.

Откуда взялось слово «асинхронный»

Синхронный — «в одно время». Всё по порядку, шаг за шагом.

Асинхронный — «не в одно время». Код может отправить задачу и продолжить, не дожидаясь.

Event Loop — как это устроено внутри

У JS есть один поток — он может делать только одно дело за раз. Но есть Event Loop — механизм, который управляет очередью задач.

Упрощённо:

  • Есть стек вызовов — где выполняется текущий код.
  • Есть очередь задач — где ждут асинхронные операции (таймеры, запросы).
  • Event Loop следит: когда стек пуст, берёт первую задачу из очереди и выполняет её.
Стек: [console.log("1")]
        ↓
Стек пуст → Event Loop берёт из очереди
        ↓
Стек: [console.log("3")]
        ↓
Стек пуст → Event Loop берёт setTimeout
        ↓
Стек: [console.log("2 (через 2 секунды)")]

Поэтому «3» выводится раньше «2»: setTimeout попадает в очередь, а не выполняется сразу.

Где это встречается в реальной жизни

  • fetch — запрос к серверу. Нельзя ждать, пока сервер ответит, иначе страница замрёт.
  • setTimeout / setInterval — таймеры.
  • addEventListener — обработчики кликов. Они тоже асинхронны: код не ждёт, когда ты кликнешь, он просто «слушает».
  • localStorage — синхронный, но быстрый. А вот IndexedDB — уже асинхронный.
  • Загрузка картинок и файлов — асинхронная.

Почему об этом важно знать

Когда начнёшь работать с fetch (а это будет уже в теме 30), код будет выглядеть так:

fetch("https://api.example.com/data")
  .then(response => response.json())
  .then(data => {
    console.log(data);
  });

console.log("это выведется раньше!");

Без понимания асинхронности это выглядит как магия. С пониманием — логично: fetch отправил запрос, пошёл дальше, а когда данные пришли — вызвал .then().

Главное из темы

  • Синхронный код — строка за строкой. Асинхронный — не ждёт.
  • Асинхронность нужна, чтобы страница не замирала на время долгих операций.
  • setTimeout, fetch, addEventListener — асинхронные.
  • Event Loop управляет очередью задач: когда стек пуст, берёт следующую.
  • Асинхронный код может выполняться не в том порядке, в каком написан.
