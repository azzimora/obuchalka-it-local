fetch: запросы к серверу

как получать данные из интернета
главная› Web›30
◈ теория

fetch — это встроенная функция JS для отправки запросов на сервер. С её помощью страница может получить данные из интернета, не перезагружаясь.

Это то, что делает современные сайты «живыми»: погода обновляется, лента подгружается, поиск работает без перезагрузки — всё через fetch.

Базовый синтаксис

fetch("https://api.example.com/data")
  .then(response => response.json())
  .then(data => {
    console.log(data);
  })
  .catch(error => {
    console.log("ошибка:", error);
  });

Что происходит по шагам:

  • fetch(url) — отправляет запрос. Возвращает Promise.
  • .then(response => ...) — когда сервер ответил, получаем объект response.
  • response.json() — читает тело ответа как JSON. Тоже возвращает Promise.
  • Второй .then(data => ...) — когда JSON разобран, получаем готовые данные.
  • .catch() — если что-то пошло не так.

С async / await — читается лучше

async function loadData() {
  try {
    const response = await fetch("https://api.example.com/data");
    const data = await response.json();
    console.log(data);
  } catch (error) {
    console.log("ошибка:", error);
  }
}

loadData();

Современный код пишется именно так. Оба варианта рабочие, но этот проще.

Что такое API

API (Application Programming Interface) — это «точка входа», через которую программы общаются друг с другом. Веб-API — это адрес в интернете, по которому можно запросить данные и получить их в формате JSON.

Примеры публичных API, которые можно использовать бесплатно:

  • JSONPlaceholder — jsonplaceholder.typicode.com — тестовые данные (посты, пользователи, комментарии);
  • Cat Fact — catfact.ninja/fact — случайные факты о котах;
  • Dog CEO — dog.ceo/api/breeds/image/random — случайные фото собак;
  • Open-Meteo — api.open-meteo.com — погода (без ключа);
  • GitHub API — api.github.com — информация о пользователях и репозиториях.

Пример: случайный факт о коте

async function getCatFact() {
  const response = await fetch("https://catfact.ninja/fact");
  const data = await response.json();
  console.log(data.fact);
}

getCatFact();

Сервер возвращает JSON вида:

{
  "fact": "Кошки спят около 70% своей жизни.",
  "length": 38
}

Мы берём data.fact — и получаем текст.

HTTP-методы

Запросы бывают разные. Основные:

Метод Что делает
GET Получить данные (по умолчанию)
POST Отправить новые данные
PUT / PATCH Обновить существующие данные
DELETE Удалить данные

По умолчанию fetch использует GET. Для других методов нужно указать их в параметрах:

fetch("https://api.example.com/posts", {
  method: "POST",
  headers: {
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    title: "Новый пост",
    body: "Текст поста"
  })
})
  .then(response => response.json())
  .then(data => console.log(data));

Проверка статуса ответа

fetch не отклоняется при ошибках на сервере (например, 404). Он отклоняется только при сетевых ошибках. Поэтому надо проверять статус вручную:

async function loadData() {
  const response = await fetch("https://api.example.com/data");
  
  if (!response.ok) {
    throw new Error(`Ошибка: ${response.status}`);
  }
  
  const data = await response.json();
  return data;
}

response.ok — true, если статус 200–299. Иначе false.

Коды статусов, которые полезно знать:

  • 200 — OK, всё хорошо;
  • 404 — не найдено;
  • 500 — ошибка сервера;
  • 401 / 403 — нет доступа.

Пример: вывод данных на страницу

<button id="load">загрузить факт</button>
<p id="fact"></p>

<script>
  document.getElementById("load").addEventListener("click", async () => {
    const factEl = document.getElementById("fact");
    factEl.textContent = "загрузка...";
    
    try {
      const response = await fetch("https://catfact.ninja/fact");
      const data = await response.json();
      factEl.textContent = data.fact;
    } catch (error) {
      factEl.textContent = "не удалось загрузить";
      console.log(error);
    }
  });
</script>

CORS — что это и почему иногда не работает

Браузер по умолчанию запрещает странице делать запросы к другим сайтам, если те не разрешили. Это называется CORS (Cross-Origin Resource Sharing).

Если API не настроен на разрешение запросов откуда угодно — fetch вернёт ошибку CORS. Это не твоя ошибка, это политика безопасности браузера.

Публичные API (те, что я перечислила выше) обычно настроены правильно — с ними всё будет работать.

fetch в реальной жизни

Почти любой современный сайт использует fetch:

  • загрузка комментариев под постом;
  • обновление ленты в соцсети;
  • поиск с подсказками;
  • отправка формы без перезагрузки;
  • загрузка картинок и видео;
  • чат в реальном времени.

Главное из темы

  • fetch отправляет HTTP-запросы из JS.
  • Возвращает Promise. Читается через .then() или async / await.
  • Тело ответа читается через response.json().
  • Методы: GET (по умолчанию), POST, PUT, DELETE.
  • Проверяй response.ok — fetch не отклоняется при 404 или 500.
  • CORS — политика безопасности браузера. Публичные API работают без проблем.
