В прошлой теме мы научились делать запросы. Теперь — как строить с ними настоящие интерфейсы: с загрузкой, ошибками, повторными попытками, кэшем.

Правильный паттерн: три состояния

Любой запрос к API имеет три состояния. Интерфейс должен отражать каждое.

  • Загрузка — показываем индикатор («загрузка...», спиннер);
  • Успех — показываем данные;
  • Ошибка — показываем понятное сообщение и, возможно, кнопку «попробовать снова».

Пример:

async function loadData() {
  const container = document.getElementById("content");
  
  // 1. Загрузка
  container.innerHTML = "<div class='loader'>загрузка...</div>";
  
  try {
    const response = await fetch("https://api.example.com/data");
    
    if (!response.ok) {
      throw new Error(`Сервер вернул ${response.status}`);
    }
    
    const data = await response.json();
    
    // 2. Успех
    container.innerHTML = "";
    data.forEach(item => {
      const el = document.createElement("div");
      el.textContent = item.title;
      container.appendChild(el);
    });
    
  } catch (error) {
    // 3. Ошибка
    container.innerHTML = `
      <div class='error'>
        Не удалось загрузить: ${error.message}
        <button onclick='loadData()'>попробовать снова</button>
      </div>
    `;
  }
}

Этот паттерн работает везде: загрузка постов, погоды, комментариев, поиска.

Разделение на функции

Не пиши всё в одном месте. Разделяй:

// 1. Функция для запроса
async function fetchUsers() {
  const response = await fetch("https://jsonplaceholder.typicode.com/users");
  if (!response.ok) throw new Error("не удалось загрузить");
  return await response.json();
}

// 2. Функция для отрисовки
function renderUsers(users) {
  const container = document.getElementById("users");
  container.innerHTML = "";
  users.forEach(user => {
    const card = document.createElement("div");
    card.className = "user-card";
    card.innerHTML = `
      <h3>${user.name}</h3>
      <p>${user.email}</p>
    `;
    container.appendChild(card);
  });
}

// 3. Функция, которая всё связывает
async function loadAndRender() {
  const container = document.getElementById("users");
  container.innerHTML = "загрузка...";
  
  try {
    const users = await fetchUsers();
    renderUsers(users);
  } catch (error) {
    container.innerHTML = "ошибка: " + error.message;
  }
}

loadAndRender();

Три маленькие функции вместо одной большой. Каждая — про своё.

Передача параметров в запрос

Часто нужно запросить данные по условию. Например, посты конкретного пользователя.

async function fetchPostsByUser(userId) {
  const url = `https://jsonplaceholder.typicode.com/posts?userId=${userId}`;
  const response = await fetch(url);
  return await response.json();
}

fetchPostsByUser(1).then(posts => console.log(posts));

Параметры после ? — это query string. Несколько параметров разделяются &.

Поиск с debounce

Классический сценарий: пользователь вводит текст, и мы делаем запрос. Но не на каждую букву — а когда он остановился.

let searchTimer;

input.addEventListener("input", () => {
  clearTimeout(searchTimer);
  
  searchTimer = setTimeout(async () => {
    const query = input.value.trim();
    if (!query) return;
    
    try {
      const results = await searchAPI(query);
      renderResults(results);
    } catch (error) {
      showError(error);
    }
  }, 500);
});

Debounce экономит запросы и не спамит сервер.

Кэширование

Если данные редко меняются, их можно сохранить — и не запрашивать каждый раз.

const cache = {};

async function fetchWithCache(url) {
  if (cache[url]) {
    console.log("из кэша");
    return cache[url];
  }
  
  const response = await fetch(url);
  const data = await response.json();
  cache[url] = data;
  return data;
}

Простой кэш в памяти. Если данные нужны надолго — можно сохранить в localStorage.

Повторные попытки при ошибке

Иногда сервер временно недоступен. Можно попробовать ещё раз:

async function fetchWithRetry(url, attempts = 3) {
  for (let i = 0; i < attempts; i++) {
    try {
      const response = await fetch(url);
      if (!response.ok) throw new Error(`статус ${response.status}`);
      return await response.json();
    } catch (error) {
      console.log(`попытка ${i + 1} не удалась`);
      if (i === attempts - 1) throw error;
      await new Promise(r => setTimeout(r, 1000));
    }
  }
}

Пробует до трёх раз с паузой в секунду. Если все попытки провалились — выбрасывает ошибку.

Что важно на практике

  • Всегда проверяй response.ok. fetch не отклоняется сам при 404 или 500.
  • Показывай состояние загрузки. Иначе пользователь думает, что сайт завис.
  • Обрабатывай ошибки. «Не удалось загрузить» лучше, чем пустой экран.
  • Разделяй запрос и отрисовку. Одна функция — одна задача.
  • Не делай запросы на каждое нажатие клавиши. Используй debounce.
  • Кэшируй, если данные не меняются.
  • Для важных запросов — повторные попытки.

Главное из темы

  • Три состояния: загрузка, успех, ошибка. Все три надо показывать.
  • Разделяй код: fetch, рендер, связка.
  • Параметры в URL — через ?key=value.
  • Debounce для поиска.
  • Кэш и повторные попытки — для надёжности.
