Замыкания и область видимости

как функции «помнят» своё окружение
главная› Web›34
◈ теория

Это одна из самых сложных тем в JavaScript. Но она важна: замыкания встречаются везде — в обработчиках событий, в модулях, в классах, в React.

Разберём по шагам.

Область видимости (scope)

Область видимости — это где переменная «видна». В JS три уровня:

  • Глобальная — доступна везде;
  • Функциональная — видна только внутри функции;
  • Блочная — видна только внутри { } блока (let и const).
const global = "я видна везде";

function example() {
  const inFunction = "я видна только внутри функции";
  console.log(global);     // ок
  console.log(inFunction); // ок
}

example();
console.log(global);     // ок
// console.log(inFunction); // ошибка

let, const и var — разница

let и const — блочные. var — функциональная (устаревшая).

if (true) {
  let a = 1;
  const b = 2;
  var c = 3;
}

// console.log(a);  // ошибка — a только внутри блока
// console.log(b);  // ошибка
console.log(c);     // 3 — var «протекает» наружу

Именно поэтому var больше не используют — он создаёт баги.

Что такое замыкание

Замыкание — это функция, которая «помнит» переменные из места, где она была создана, даже если это место уже завершило работу.

Пример:

function outer() {
  const message = "привет";
  
  function inner() {
    console.log(message);  // ← берёт message из outer
  }
  
  return inner;
}

const fn = outer();  // outer выполнилась и завершилась
fn();                // "привет" — хотя outer уже не работает!

Функция inner «запомнила» переменную message, хотя outer уже завершилась. Это и есть замыкание.

Зачем это нужно: счётчик

Классический пример — счётчик, который не сбрасывается:

function createCounter() {
  let count = 0;
  
  return function() {
    count++;
    return count;
  };
}

const counter1 = createCounter();
console.log(counter1());  // 1
console.log(counter1());  // 2
console.log(counter1());  // 3

const counter2 = createCounter();  // ← новый счётчик, своё count
console.log(counter2());  // 1

У каждого счётчика — своё count. Они не мешают друг другу. Это возможно именно благодаря замыканию.

Приватные переменные через замыкание

До появления приватных полей в классах (#), замыкания использовали для инкапсуляции:

function createBank() {
  let balance = 0;
  
  return {
    deposit(amount) {
      balance += amount;
    },
    withdraw(amount) {
      if (amount > balance) {
        return "недостаточно средств";
      }
      balance -= amount;
    },
    getBalance() {
      return balance;
    }
  };
}

const bank = createBank();
bank.deposit(100);
bank.withdraw(30);
console.log(bank.getBalance());  // 70
// console.log(bank.balance);    // undefined — снаружи не достать

balance живёт внутри замыкания и недоступен снаружи. Работает как приватное поле.

Замыкания в обработчиках событий

Это то, где ты уже сталкивалась с замыканиями, даже не зная об этом:

function createButton(label) {
  const btn = document.createElement("button");
  btn.textContent = label;
  
  btn.addEventListener("click", () => {
    console.log(`нажата кнопка: ${label}`);  // ← замыкание на label
  });
  
  return btn;
}

document.body.appendChild(createButton("старт"));
document.body.appendChild(createButton("стоп"));

У каждой кнопки — своя label, запомненная в замыкании.

Классическая ловушка с циклом и var

Старый баг, который многих путал:

for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// выведет: 3, 3, 3
// хотя ожидалось: 0, 1, 2

Почему? Потому что var — функциональная, а не блочная. Все замыкания видят одну и ту же переменную i, которая к моменту выполнения стала 3.

Решение — использовать let:

for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// выведет: 0, 1, 2

let создаёт новую переменную на каждую итерацию. Это одна из причин, почему let и const стали стандартом.

Где замыкания используются на практике

  • Счётчики и фабрики функций — createCounter(), createButton().
  • Приватные переменные — до появления # в классах.
  • Обработчики событий — каждый запоминает своё.
  • debounce и throttle — сохраняют таймер между вызовами.
  • Модули — каждая «сборка» имеет своё окружение.
  • React-хуки — useState работает через замыкание.

Важно не путать

Замыкание — это не «функция внутри функции». Это функция, которая запоминает переменные снаружи. Если внутри функции не используется ничего снаружи — это просто функция, не замыкание.

Главное из темы

  • Область видимости: глобальная, функциональная, блочная.
  • let и const — блочные, var — функциональная (не использовать).
  • Замыкание — функция, которая помнит переменные снаружи.
  • Используется для счётчиков, приватности, обработчиков.
  • Ловушка с var и циклом решается через let.

Цель: увидеть замыкания руками и научиться их использовать.

  • Создай файл closures.html с обычным каркасом. Открой, F12 → Console.
  • Задание 1 — первый счётчик. Напиши createCounter() из теории. Создай два счётчика, понажимай каждый. Убедись, что у них свои значения.
  • Задание 2 — счётчик с шагом. Сделай createCounter(step), где каждая итерация прибавляет step. По умолчанию 1. Проверь с шагом 5.
  • Задание 3 — банк. Напиши createBank() с приватным балансом, методами deposit, withdraw (с проверкой), getBalance. Проверь, что bank.balance снаружи — undefined.
  • Задание 4 — фабрика кнопок. Напиши createButton(label, color), которая создаёт кнопку с заданным текстом и цветом. При клике — консоль выводит название. Создай 3 кнопки на странице.
  • Задание 5 — ловушка с var. Напиши цикл for (var i = 0; i < 3; i++) с setTimeout, который выводит i. Посмотри результат. Замени var на let — снова посмотри. Запиши, что изменилось и почему.
  • Задание 6 — debounce через замыкание. Напиши функцию debounce(fn, delay), которая возвращает новую функцию, выполняющую fn только через delay мс после последнего вызова. Используй её для поля ввода.
  • Бонус — throttle. Напиши throttle(fn, limit) — функция выполняется не чаще, чем раз в limit мс. Используй для скролла.
